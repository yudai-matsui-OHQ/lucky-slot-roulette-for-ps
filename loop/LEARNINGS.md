# LEARNINGS — 失敗から得たルール集

ループで発生した失敗・エラー・手戻りを「次のループが同じミスをしないためのルール」に変換して蓄積する。
STATE.md が「何をしたか」の記録なのに対し、ここは「どうすべきか」の抽出。**新しいループは作業前に必ずここを読む。**

運用:

- 書式: `- [タグ] ルール(命令形で書く) — 根拠となった失敗と日付`
- 事実の羅列ではなく**行動可能なルール**として書く。「〜が起きた」ではなく「〜せよ / 〜するな」
- 同じ原因の失敗が再発したら、新規追記ではなく既存ルールを強化する(表現の明確化・タグ追加)
- 同じルールが3回以上参照・再発したら、CLAUDE.md または該当スキルへの昇格を提案する(恒久知識化)
- 陳腐化したルール(環境が変わって不要になった等)は削除し、削除理由を STATE.md に残す

## ルール

- [環境] サンドボックスで `npm install` が失敗(レジストリ502)しても再試行で粘らない。バージョン確認は web_fetch で `registry.npmjs.org/<pkg>/latest` を参照し、package.json への追記までに留めて install はローカル作業として STATE に引き継ぐ — 2026-07-02 vitest導入時に約10分浪費
- [環境] `.claude/` 配下はセッションによって書き込み保護される。スキル・エージェント定義の実体は `loop/skills/`・`loop/agents/` に置き、symlink で登録する — 2026-07-02 スキル作成時に書き込み拒否
- [テスト] DOM 環境(jsdom等)が無い前提でフック本体を直接テストしない。先にロジックを純粋関数へ抽出(挙動不変リファクタ)してからテストする — 2026-07-02 useLocalStorage / useRoulette で確立したパターン
- [型] `it.each` は vitest 型が解決できない状態で暗黙 any を生む。テーブルテストは明示的に型注釈した cases 配列 + for ループで書く — 2026-07-02 constants.test.ts
- [後方互換] localStorage キーを定数化・移動するときは、旧文字列と新文字列を diff 上で1文字単位(特に大文字小文字)で突き合わせる。tsc / eslint / 既存テストは文字列リテラルの値の誤りを検出できない — 2026-07-07 フェーズ2演習で casing 崩れが後方互換を破壊(verifier が検出)
- [テスト] STORAGE_KEYS のような外部永続化キーは、リテラル値を assert するテストで固定する。キー名変更 = データマイグレーション課題であることをテストで顕在化させる — 2026-07-07 同上、constants.test.ts に導入済み
- [エージェント] エージェント定義とタスク指示が矛盾する場合、エージェントは定義側を優先する(健全)。検出演習のバグはエージェントに仕込ませず、オーケストレーターが直接仕込む — 2026-07-07 implementer が演習指示を定義違反として拒否
- [テスト] 完了条件が「Xを検証する」でも実装がXを満たさない場合、期待値を捏造してテストを緑にしない。実挙動を pin し、なぜそうなるか(例: useState 初期化子は初回のみ・key 監視 useEffect 無し)をコメントで顕在化し、修正/仕様判断を follow-up として BACKLOG に起票する — 2026-07-07 useLocalStorage が key 変更で storedValue を再読込しない件
- [報告] implementer のテスト件数など数値の自己申告を信用しない。verifier は新規テストファイルを単体実行(`vitest run <file>`)して件数を突合する — 2026-07-07 「8テスト」申告に対し実際は7だった
- [テスト環境] DOM が必要なテストは vite.config.ts をグローバルに変えず、ファイル先頭の `// @vitest-environment jsdom` ディレクティブで局所的に切替える(スコープ最小・純粋関数テストは node 環境のまま)。ディレクティブが効いているかは単体実行で確認する — 2026-07-07 useLocalStorage.hook.test.ts
- [スコープ] テスト対象のロジックが想定した場所に無いことがある(例: 重み計算は useMembers ではなく useRoulette.spin にあった)。着手前に実装箇所を grep で確認し、タスク記述と実態がずれていたら BACKLOG の記述を直してから実装する — 2026-07-02 重み付けテスト追加時
